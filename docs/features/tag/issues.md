| #   | 제목                                    | 의존 |

#2, #3, #5, #6은 #1 완료 후 서로 독립적이라 병렬 진행이 가능하다. #4는 #3이 만든 안내 문구 상태와 표시를 재사용하므로 #3 완료 후에 진행한다(#3과 #4는 둘 다 `validateTag`를 수정하므로 순차 진행).

## 공통 사항

- TDD로 진행한다. 규칙은 `utils` 단위 테스트, 상태는 `renderHook`, 표현 컴포넌트는 props 기반 테스트, `NoteEditor`는 통합 테스트(`api` mock 또는 `NotesProvider`)로 검증한다.
- 태그가 없는 기존 노트(`tags` 없음, `db.json` 무수정)는 모든 이슈에서 `note.tags ?? []`로 처리하며 에러가 나지 않아야 한다.
- 새 UI 문구는 한국어, 입력 요소에는 `aria-label`을 단다. 스타일은 `docs/design-system/`을 따른다.
- 서버 반영은 기존 "저장" 버튼에서만 한다. 응답 후 Context 배열을 갱신하고 재조회하지 않는다.

## 이슈 1. 기존 노트에 태그를 추가하고 저장한다

### 설명

노트 상세 화면에서 태그를 입력해 붙이고, "저장"으로 서버에 반영해 다시 열어도 태그가 유지되는 핵심 경로를 end-to-end로 만든다. 이후 이슈의 기반이 되는 워킹 스켈레톤이다. `db.json`에 태그 데이터가 없어서 "표시만" 먼저 만들 수 없으므로 추가, 표시, 저장을 한 이슈로 묶는다.

### 관통 범위

- 타입: `src/types/note.ts`에 `tags?: string[]` 추가, "tags 필드는 아직 없음" 주석 정리
- 규칙: `src/utils/tags.ts`의 `validateTag(input, existing)` — 이번 이슈에서는 trim, 빈 값 무시만
- 상태: `src/hooks/useTagEditor.ts` — `tags`, `isInputOpen`, `inputValue`와 `toggleInput`, `changeInput`, `addTag`, `reset(initialTags)`
- 표현: `Tag`(삭제 버튼 없는 최소형), `TagInput`, `TagList`
- 조립: `NoteEditor` — 제목 아래에 배치, 저장 시 PATCH 페이로드에 `tags` 포함, 노트 전환 시 `reset`

### 완료조건 (Acceptance Criteria)

- [ ] 제목 입력 바로 아래에 회색 계열의 "태그 추가" 버튼이 있다.
- [ ] 버튼을 누르면 버튼 오른쪽에 태그 입력창이 나타나고 버튼명이 "닫기"로 바뀐다. "닫기"를 누르면 입력창이 사라지고 "태그 추가"로 돌아온다.
- [ ] 입력창에서 Enter를 누르면 trim된 태그가 한 개 추가된다. 폼 submit은 일어나지 않는다(`preventDefault`).
- [ ] 추가 후 입력창은 비워지고 열린 상태를 유지한다(연속 입력 가능).
- [ ] 빈 값 또는 공백만 입력하고 Enter를 눌러도 태그가 추가되지 않고 메시지도 표시되지 않는다.
- [ ] 추가된 태그가 입력 영역 아래에 `flex-wrap`으로 실시간 표시된다. 태그가 없으면 목록 영역에 아무것도 표시하지 않는다.
- [ ] "저장"을 누르면 PATCH 페이로드에 `title`, `content`, `tags`가 함께 포함되고, 응답 후 Context 배열이 갱신된다.
- [ ] 저장한 노트를 다시 열면 `tags`가 그대로 표시된다.
- [ ] `tags`가 없는 기존 노트를 열고 저장해도 에러가 나지 않는다.
- [ ] 노트를 전환(`selectedNoteId` 변경)하면 `title`, `content`, `tags`가 함께 리셋되고, 입력창은 닫히며 입력 중이던 텍스트가 초기화된다. 이전 노트의 태그가 섞이지 않는다.
- [ ] 태그 입력창에 `aria-label`이 있다.

### 시나리오 (Given / When / Then)

**시나리오 1-1. 입력창 열고 닫기**

- Given: 노트 하나를 선택해 NoteEditor가 열려 있고 입력창은 닫혀 있다.
- When: "태그 추가" 버튼을 누른다.
- Then: 버튼 오른쪽에 태그 입력창이 나타나고 버튼명이 "닫기"로 바뀐다. 다시 "닫기"를 누르면 입력창이 사라지고 버튼은 "태그 추가"로 돌아온다.

**시나리오 1-2. Enter로 태그 연속 추가**

- Given: 태그 입력창이 열려 있고 노트에 태그가 없다.
- When: `  react  `를 입력하고 Enter를 누른 뒤, 이어서 `design`을 입력하고 Enter를 누른다.
- Then: `react`, `design` 순서로 입력 영역 아래에 태그가 표시된다(앞뒤 공백 제거). 입력창은 비워진 채 열려 있고 폼은 submit되지 않는다.

**시나리오 1-3. 빈 값 무시**

- Given: 태그 입력창이 열려 있다.
- When: 아무것도 입력하지 않거나 공백만 입력하고 Enter를 누른다.
- Then: 태그가 추가되지 않고 안내 문구도 표시되지 않는다.

**시나리오 1-4. 저장 후 유지**

- Given: 노트에 `react` 태그를 추가했다(아직 저장 전).
- When: "저장" 버튼을 누른 뒤 다른 노트로 이동했다가 다시 이 노트를 연다.
- Then: PATCH 요청에 `title`, `content`, `tags: ["react"]`가 포함되었고, 다시 연 노트에 `react` 태그가 표시된다.

**시나리오 1-5. 태그가 없는 기존 노트**

- Given: `db.json`의 기존 노트처럼 `tags` 필드가 없는 노트가 있다.
- When: 이 노트를 열고 제목만 수정해 저장한다.
- Then: 에러 없이 열리고, 태그 목록 영역은 비어 있으며, 저장이 정상 완료된다.

**시나리오 1-6. 노트 전환 시 리셋**

- Given: 노트 A에서 입력창을 열고 `react`를 추가했으며 입력창에 `des`를 입력 중이다(저장 전).
- When: 노트 B를 선택한다.
- Then: 노트 B의 저장된 태그만 표시되고, 입력창은 닫혀 있으며, 입력 중이던 `des`와 안내 문구는 초기화된다. 노트 A의 미저장 `react`는 노트 B에 나타나지 않고 확인창도 뜨지 않는다.

### 테스트

- `validateTag` 단위(trim, 빈 값), `useTagEditor` `renderHook`(토글, 추가, `reset`), `NoteEditor` 통합(저장 페이로드에 `tags` 포함, `tags` 없는 노트, 노트 전환), `api/notes.ts` 페이로드에 `tags`가 통과하는지 확인.

## 이슈 2. 태그를 삭제한다

### 설명

잘못 붙인 태그를 `x` 버튼으로 제거한다. 삭제는 로컬 `tags` state에 먼저 반영하고, "저장"을 눌러야 서버에 반영된다. 긴 태그가 레이아웃을 깨뜨리지 않도록 `Tag`의 최대 너비를 제한하고 말줄임 처리한다. 말줄임이 되어도 `x` 버튼에 접근할 수 있어야 하므로 삭제 버튼과 같은 이슈에서 다룬다.

### 관통 범위

- 표현: `Tag`에 `x` 삭제 버튼과 `onDelete` 추가, 최대 너비 제한과 `truncate` 말줄임, 전체 이름을 `title` 속성으로 제공, `TagList`가 콜백 전달
- 상태: `useTagEditor.removeTag`
- 조립: `NoteEditor`에서 `removeTag` 연결

### 완료조건 (Acceptance Criteria)

- [ ] 각 태그에 삭제용 `x` 버튼이 DOM에 항상 존재한다.
- [ ] `x` 버튼은 평소에는 투명하고, 태그에 마우스를 올리거나(`group-hover`) 버튼에 키보드 포커스가 오면(`focus`) 보인다.
- [ ] `x` 버튼에 `aria-label="{태그명} 태그 삭제"`가 있다.
- [ ] 삭제는 `onDelete` 콜백으로 부모에 위임하고, 클릭하면 해당 태그가 목록에서 즉시 사라진다.
- [ ] 삭제 후 "저장"을 누르면 서버에 반영되고, 저장 전에 노트를 전환하면 삭제가 버려진다(확인창 없음).
- [ ] 모든 태그를 삭제하면 목록 영역에 아무것도 표시하지 않는다.
- [ ] `Tag` 박스에 최대 너비가 설정되어 있고, 넘치는 라벨은 `truncate`로 말줄임 처리된다.
- [ ] `title` 속성에 전체 태그 이름이 들어 있어 호버 시 전체 이름이 보인다.
- [ ] 말줄임이 되어도 `x` 삭제 버튼은 잘리지 않고 접근할 수 있다.
- [ ] 50자 태그를 여러 개 추가해도 목록이 `flex-wrap`으로 줄바꿈되고 가로 스크롤이 생기지 않는다.

### 시나리오 (Given / When / Then)

**시나리오 2-1. 태그 삭제 후 저장**

- Given: 노트에 `react`, `design` 태그가 저장되어 있다.
- When: `react` 태그의 `x` 버튼을 누르고 "저장"을 누른다.
- Then: 목록에 `design`만 남고, PATCH 페이로드에 `tags: ["design"]`이 포함된다.

**시나리오 2-2. 키보드로 삭제**

- Given: 태그가 표시되어 있고 `x` 버튼이 투명한 상태이다.
- When: 키보드 Tab으로 `x` 버튼에 포커스를 옮긴다.
- Then: `x` 버튼이 보이고, 스크린리더가 `"react 태그 삭제"`로 읽을 수 있다.

**시나리오 2-3. 저장 전 노트 전환**

- Given: 저장된 `react` 태그를 삭제했지만 아직 "저장"하지 않았다.
- When: 다른 노트로 이동했다가 이 노트로 돌아온다.
- Then: 서버 저장값 기준으로 `react` 태그가 그대로 표시된다.

**시나리오 2-4. 긴 태그 표시**

- Given: 50자 길이의 태그가 노트에 추가되어 있다.
- When: NoteEditor에서 태그 목록을 렌더링한다.
- Then: 태그 박스는 최대 너비에서 말줄임(`…`)으로 표시되고, `title` 속성에 전체 이름이 들어 있다.

**시나리오 2-5. 긴 태그 삭제**

- Given: 말줄임 처리된 긴 태그가 표시되어 있다.
- When: 태그에 마우스를 올리거나 `x` 버튼에 포커스를 둔다.
- Then: `x` 버튼이 잘리지 않고 보이며 클릭해 삭제할 수 있다.

### 테스트

- `Tag` props 테스트(`onDelete` 호출, `aria-label`, `title` 속성, `truncate` 클래스), `useTagEditor.removeTag`, `NoteEditor` 통합(삭제 후 저장 페이로드).

## 이슈 3. 중복 태그를 막는다

### 설명

같은 태그가 두 번 들어가지 않도록 막고, 중복이면 입력창 아래에 안내 문구를 보여준다. 중복 판정은 trim 후 대소문자를 무시하며, 저장은 처음 입력한 표기 그대로 한다.

### 관통 범위

- 규칙: `validateTag`에 중복 검사 추가(추가 가능 여부, 정규화된 값, 안내 문구 반환)
- 상태: `useTagEditor`에 안내 문구 상태(`errorMessage`) 추가, `addTag`가 검증 결과를 반영
- 표현: `TagInput`이 입력창 아래에 안내 문구 표시
- 조립: 노트 전환 시 `reset`에서 안내 문구 초기화

### 완료조건 (Acceptance Criteria)

- [ ] trim 후 대소문자를 무시하고 비교했을 때 이미 있는 태그면 추가되지 않는다.
- [ ] 중복이면 입력창 아래에 "이미 있는 태그입니다"를 표시한다.
- [ ] 저장되는 표기는 처음 입력한 것 그대로다(`React` 뒤에 `react`를 입력해도 `React`가 유지).
- [ ] 노트 전환 시 안내 문구가 초기화된다.
- [ ] 중복으로 거절되면 입력창의 값은 비워지지 않고 유지된다(수정해서 다시 시도할 수 있다).
- [ ] 안내 문구는 입력창의 값이 바뀌는 시점(`changeInput`)에 사라진다. 거절 직후에는 입력값이 유지되므로, 사용자가 값을 수정하기 전까지 안내 문구가 계속 표시된다.

### 시나리오 (Given / When / Then)

**시나리오 3-1. 대소문자 다른 중복**

- Given: 노트에 `React` 태그가 있고 입력창이 열려 있다.
- When: `  react  `를 입력하고 Enter를 누른다.
- Then: 태그가 추가되지 않고 목록에는 `React` 하나만 남으며, 입력창 아래에 "이미 있는 태그입니다"가 표시된다. 입력창의 값은 지워지지 않고 그대로 유지된다.

**시나리오 3-2. 중복이 아닌 태그는 정상 추가**

- Given: 노트에 `React` 태그가 있고, 중복 입력으로 안내 문구가 표시되어 있다(입력창에는 `react`가 남아 있다).
- When: 입력창의 값을 `design`으로 바꾸고 Enter를 누른다.
- Then: 입력을 바꾸는 시점에 안내 문구가 사라지고, Enter를 누르면 `design`이 추가되며 입력창이 비워진다.

**시나리오 3-3. 노트 전환 시 안내 초기화**

- Given: 중복 입력으로 안내 문구가 표시되어 있다.
- When: 다른 노트를 선택한다.
- Then: 안내 문구가 사라지고 입력창은 닫힌 상태로 돌아간다.

**시나리오 3-4. 입력을 바꾸면 안내 문구가 사라진다**

- Given: 노트에 `React` 태그가 있고, `react`를 입력해 중복 안내 문구가 표시되어 있다(입력창에는 `react`가 남아 있다).
- When: 입력창에서 글자 하나를 지운다(`reac`).
- Then: 안내 문구가 즉시 사라진다. 태그는 추가되지 않은 상태 그대로다.

### 테스트

- `validateTag` 중복 케이스 단위(대소문자, 앞뒤 공백, 원본 표기 유지), `useTagEditor` 안내 문구 상태(`changeInput` 시 `errorMessage` 초기화, 중복 거절 시 `inputValue` 유지), `NoteEditor` 통합.

## 이슈 4. 태그 길이(50자)와 개수(10개)를 제한한다

### 설명

태그 하나는 최대 50자, 노트당 최대 10개로 제한한다. 초과하면 추가하지 않고 입력창 아래에 안내 문구를 보여준다.

### 관통 범위

- 규칙: `validateTag`에 길이(trim 후 기준)와 개수 검사 추가
- 상태/표현: 이슈 3의 안내 문구 상태와 `TagInput` 표시를 재사용한다(#3이 먼저 완료되어야 한다)

### 완료조건 (Acceptance Criteria)

- [ ] trim 후 50자까지는 추가되고, 51자부터는 추가되지 않으며 안내 문구가 표시된다.
- [ ] 태그가 9개일 때 10번째는 추가되고, 이미 10개일 때 추가를 시도하면 추가되지 않고 안내 문구가 표시된다.
- [ ] 길이 초과와 개수 초과 안내 문구는 서로 구분된다.
- [ ] 안내 문구는 길이 초과 시엔 "태그는 최대 50자까지 입력할 수 있습니다", 개수 초과 시엔 "태그는 최대 10개까지 추가할 수 있습니다"
- [ ] 길이/개수 초과로 거절되어도 입력창의 값은 유지되고, 안내 문구가 사라지는 시점은 #3과 같다(입력창의 값이 바뀔 때).
- [ ] 경계값(50/51자, 10/11개)을 `validateTag` 단위 테스트에 포함한다.
- [ ] 개수 제한은 로컬 `tags` 기준이며, 태그를 삭제하면 다시 추가할 수 있다.

### 시나리오 (Given / When / Then)

**시나리오 4-1. 길이 초과**

- Given: 태그 입력창이 열려 있다.
- When: 51자 문자열을 입력하고 Enter를 누른다.
- Then: 태그가 추가되지 않고 길이 초과 안내 문구가 표시된다. 정확히 50자를 입력하면 정상 추가된다.

**시나리오 4-2. 개수 초과**

- Given: 노트에 태그가 이미 10개 있다.
- When: 새 태그를 입력하고 Enter를 누른다.
- Then: 태그가 추가되지 않고 개수 초과 안내 문구가 표시된다.

**시나리오 4-3. 삭제 후 다시 추가**

- Given: 태그가 10개 있고 개수 초과 안내가 표시된 상태이다.
- When: 태그 하나를 삭제하고 새 태그를 입력해 Enter를 누른다.
- Then: 새 태그가 추가되어 다시 10개가 된다.

### 테스트

- `validateTag` 경계값 단위, `useTagEditor`의 안내 문구 구분, `NoteEditor` 통합.

## 이슈 5. 새 노트 작성 중에도 태그를 추가한다

### 설명

새 노트 작성(`isCreating`) 중에도 같은 방식으로 태그를 추가하고, "저장" 시 새 노트가 `tags`와 함께 생성되도록 한다.

### 관통 범위

- Context: `NotesContext.createNote`가 `tags`를 받도록 확장(`updateNote`는 변경 없음)
- API: `api.createNote` 페이로드에 `tags` 포함 확인
- 조립: `NoteEditor`의 생성 경로에서 `tags` 전달

### 완료조건 (Acceptance Criteria)

- [ ] 새 노트 작성 화면에서 #1에서 구현한 태그 입력 동작(입력창 열기/닫기, Enter로 추가, 목록 표시)이 그대로 동작한다.
- [ ] "저장" 시 POST 페이로드에 `title`, `content`, `tags`가 포함된다.
- [ ] 태그를 추가하지 않으면 `tags: []`를 보낸다.
- [ ] 생성 후 목록에 나타난 노트를 열면 저장한 태그가 표시된다.
- [ ] 새 노트 작성 중 다른 노트를 선택하거나 새 노트를 다시 시작하면 태그와 입력창 상태가 리셋된다.

### 시나리오 (Given / When / Then)

**시나리오 5-1. 태그와 함께 생성**

- Given: "+ 새 노트"를 눌러 작성 화면이 열려 있고 제목과 내용을 입력했다.
- When: 태그 `react`를 추가하고 "저장"을 누른다.
- Then: POST 요청에 `tags: ["react"]`가 포함되고, 목록에 새 노트가 생기며, 그 노트를 열면 `react`가 보인다.

**시나리오 5-2. 태그 없이 생성**

- Given: 새 노트 작성 화면에서 제목과 내용만 입력했다.
- When: "저장"을 누른다.
- Then: POST 요청에 `tags: []`가 포함된다.

**시나리오 5-3. 작성 중 전환**

- Given: 새 노트 작성 중 태그 `react`를 추가했다(저장 전).
- When: 기존 노트를 선택한다.
- Then: 작성 중이던 태그는 버려지고 확인창은 뜨지 않으며, 선택한 노트의 저장된 태그만 표시된다.

### 테스트

- `api.createNote` 페이로드 테스트, `NotesContext.createNote` 인자 확장 테스트, `NoteEditor` 생성 경로 통합.

## 이슈 6. 노트 목록 카드에 태그 개수를 표시한다

### 설명

왼쪽 노트 목록의 카드(`NoteItem`)에서 태그가 있는 노트를 열지 않고도 구분할 수 있도록 태그 아이콘과 개수를 표시한다. `NoteItem`만 수정하며 이슈 1의 저장된 태그를 사용한다.

### 관통 범위

- 표현: `NoteItem`이 `note.tags ?? []`의 길이로 아이콘과 개수 표시

### 완료조건 (Acceptance Criteria)

- [ ] 태그가 1개 이상인 노트 카드에 작은 태그 아이콘과 개수(예: 3)를 회색(`text-muted-foreground`)으로 표시한다.
- [ ] 태그가 없거나 `tags` 필드가 없는 노트에는 아무것도 표시하지 않는다.
- [ ] 개수는 서버에 저장된 값 기준이며, 편집 중인 미저장 태그는 반영하지 않는다.
- [ ] 태그를 저장하면 Context 갱신으로 카드의 개수가 함께 바뀐다.
- [ ] 아이콘은 장식이므로 개수가 스크린리더에 읽히도록 `aria-label` 등으로 의미를 전달한다.

### 시나리오 (Given / When / Then)

**시나리오 6-1. 태그 개수 표시**

- Given: 태그 3개가 저장된 노트가 목록에 있다.
- When: 목록을 렌더링한다.
- Then: 해당 카드에 태그 아이콘과 `3`이 표시된다.

**시나리오 6-2. 태그가 없는 노트**

- Given: `tags` 필드가 없는 기존 노트와 `tags: []`인 노트가 있다.
- When: 목록을 렌더링한다.
- Then: 두 카드 모두 태그 아이콘과 개수를 표시하지 않으며 에러가 나지 않는다.

**시나리오 6-3. 미저장 편집은 반영 안 됨**

- Given: 노트 A를 열어 태그 하나를 추가했지만 저장하지 않았다.
- When: 목록의 노트 A 카드를 확인한다.
- Then: 카드의 개수는 서버 저장값 그대로이고, "저장" 후에 갱신된다.

### 테스트

- `NoteItem` props 테스트(`tags` 있음, 빈 배열, 필드 없음).

## 구현 순서와의 대응

`spec-fixed.md`의 레이어별 구현 순서가 어느 이슈에 들어가는지 보여주는 **참고용** 표이다. 작업 순서는 위 이슈 단위(수직 슬라이스)와 의존 관계를 따르며, 이 표의 레이어 순서를 이슈 순서로 쓰지 않는다.

| `spec-fixed.md` 단계         | 들어가는 이슈                                |
| ---------------------------- | -------------------------------------------- |
| 1. `types/note.ts`           | #1                                           |
| 2. `api/notes.ts`            | #1 (PATCH 테스트), #5 (POST 테스트)          |
| 3. `NotesContext.createNote` | #5                                           |
| 4. `utils/tags.ts`           | #1 (trim, 빈 값), #3 (중복), #4 (길이, 개수) |
| 5. `Tag`                     | #1 (최소형), #2 (삭제 버튼, 말줄임)          |
| 6. `TagInput` / `TagList`    | #1, #3 (안내 문구)                           |
| 7. `useTagEditor`            | #1에서 시작해 #2~#4에서 확장                 |
| 8. `NoteEditor`              | #1, #5                                       |
| 9. `NoteItem`                | #6                                           |

## 구현 전 확인이 필요한 항목

- **태그 아이콘**: 디자인 시스템의 태그 칩(`docs/design-system/components/tag-chip.md`)은 아이콘 없이 `rounded-full`, `surface_container_highest` 배경, `on_surface_variant` 텍스트로 정의되어 있다. 정의서는 `Tag`에 태그 아이콘과 `NoteItem`에 아이콘 + 개수 표시를 명시하므로, 아이콘 사용이 디자인 시스템 Don't("기능적 명확성이 없다면 아이콘이나 이모지를 쓰지 않는다")에 맞는지 확정이 필요하다. (#1, #6)

## Out of Scope

`prd.md`의 5번(Out of Scope)을 따른다. 태그 필터링과 검색, 이름 수정, 순서 변경, 즉시 서버 반영, 미저장 이탈 확인창, 터치 기기 대응 등은 이슈로 만들지 않는다.
